# Phase 2 soak (local real-time chain, LABELLED MOCK FEEDS)

Generated by `services/scheduler/fallback/src/soak/report.ts` from onchain events only.

**This is not a testnet soak.** The testnet soak is BLOCKED: the deployer has 0 testnet MON. Per the Phase 2 prompt's fallback, this soak ran on a local real-time chain with clearly labelled mock feeds that mirror Chainlink mainnet prices.

**Soak run:** the fallback image was built from the fixed working tree at 09:16 UTC (lens snapshot, nonce manager, health changes). It ran 09:16:43 → 14:36 UTC. An earlier soak on the pre-review build was stopped after about 40 minutes; its log is not used as evidence.

**Host interruption:** between 12:11:51 and 14:35:31 UTC, *every* process froze for 2 h 23 m: the scheduler container, the local chain and the MON mirror. This happened while this session was paused at a usage limit, and is consistent with the WSL host suspending. When it resumed, the chain clock jumped forward, so the rounds that fell inside the freeze could not be created or settled in time.

**Results are split into two windows:**

- **Continuous window** (09:16 → 12:16 chain time, **3.0 h**): the table below. **26/26 rounds created ahead, opened and resolved, 0 missed, max resolve delay 43 s.** This window meets AC3's "≥ 2 h, 0 missed, ≤ 60 s", on mock feeds.
- **Full run including the freeze** (5.3 h): summarized at the end.
  - Rounds that fell inside the freeze ended INVALID, or were never created (MISSING) because their start passed while the machine was frozen.
  - **No market was left stuck in CREATED/OPEN.**
  - On resume, 3 MON INVALIDATE attempts were reported "failed" with `NotUnresolvable`. The mirror published a late round in the same second, so the derived-UNRESOLVABLE view flipped back to PENDING (the advisory-view behaviour from Phase 1). The next ticks proved that late round, which is itself UNRESOLVABLE (beyond `maxOracleDelay`), and all 3 markets ended INVALID.
  - Since then this race is classified as `waiting` rather than `failed`.

**Disclosures** (hostile review iteration 2, L-g):

- **Short stall inside the continuous window.** A 111 s wall-clock stall happened at 10:11:13 → 10:13:04 (chain clock 10:11:29 → 10:13:04). No boundary was due during it, so no result changed.
- **Clock drift.** By 12:11, chain time had drifted about +4.6 min ahead of the host clock. That is why the freeze begins at 12:11:51 host time while the window ends at 12:16:29 chain time. All delays are measured in chain time, both for the boundary and for the settling block, so the numbers are self-consistent.
- **Window chosen afterwards.** The window's end was picked after the fact (where the freeze began). An uninterrupted second run of at least 2 h would remove that choice; the testnet soak (blocked) should be that run.
- **Scope.** This soak covers only the fallback path, not CRE, and includes only 2 MON rounds; one MON open took 62 s.

Raw logs: `soak-logs/scheduler.jsonl.gz` (fallback JSON logs) and `soak-logs/mon-mirror.log.gz`.

**Setup:**

- anvil with 1 s real-time blocks, chain id 31337, Phase 1 contracts and SchedulerReceiver (`src/soak/up.ts`).
- The fallback scheduler ran in Docker (`docker-compose.yml`) as the onchain leader, with a 10 s loop.

**Feeds (LABELLED MOCK FEEDS):**

- MON/USD: the local MockAggregator is fed by `mon-mirror.ts` with every new Chainlink MON/USD round from Monad mainnet (real prices, real ~30 s cadence).
- BTC/ETH: Data Streams-shaped reports signed by the TEST signer (MockStreamsVerifierProxy, 20 s finalization window), priced from Chainlink BTC/USD and ETH/USD on Monad mainnet.

**Delay definitions:**

- open = Opened block time − start; resolve = Resolved block time − end.
- Streams proposal = the first ReportProposed block time − end. That is when settlement evidence landed; the round becomes final after the finalization window.
